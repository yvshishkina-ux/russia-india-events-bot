# Telegram-бот «Индия: бизнес и события»

Минималистичный каталог готовых событий. Worker не вызывает OpenAI, не ищет и не
парсит мероприятия и не создаёт личные кабинеты. Единственный источник контента — два
JSON-файла в GitHub. D1 хранит только Telegram chat ID подписчиков, технические
fingerprints, доставленные версии и update ID для защиты webhook от повторов.

## Структура

- `data/events.json` — только актуальные события скользящего окна 120 дней;
- `data/archive_ids.json` — минимальный след прошедших событий: ID и дата завершения;
- `src/` — GitHub-клиент, Telegram-интерфейс и синхронизация;
- `migrations/` — служебное состояние `event_state` и `published_versions`;
- `scripts/import-calendars.mjs` — объединение стартовых календарей из HTML/JSON/CSV.
- `DATA_AGENT_INSTRUCTIONS.md` — готовый контракт для агента, обновляющего GitHub.

Стартовый файл импортирован из трёх исходных HTML-календарей: 146 деловых событий
в Индии и 24 уникальных связанных с Индией события по России. Московская подборка
добавила пять новых карточек; девять пересекающихся записей объединены. Всего —
170 активных записей.

## Контракт данных

`id` должен быть постоянным и никогда не меняться при переносе события. Допустимые
географии: `IN`, `RU`; категории: `business`, `culture`, `practices`; статусы:
`scheduled`, `postponed`, `cancelled`, `online`. Даты — `YYYY-MM-DD`, ссылка — только
официальная и только HTTPS. Все тексты уже должны быть готовы к показу пользователю.

Существенными считаются только изменения `start_date`, `end_date`, `city`, `status`
и `official_url`. Описание, площадка и редактура названия повторную публикацию не
вызывают. Публикация имеет детерминированный ID `event_id:fingerprint`; уникальный
индекс D1 блокирует повторы каждому подписчику. Отмена рассылается подписчикам, после
чего отменённое событие исчезает из пользовательского каталога.

Webhook подтверждается Telegram сразу, а выдача карточек продолжается в фоне. Полученные
`update_id` фиксируются, поэтому повторная доставка одного webhook не дублирует ответы.
Зависшая служебная публикация может быть повторена через 15 минут; это закрывает сбой
между резервированием ID и вызовом Telegram API.

Прошедшее событие удаляется из `events.json`, а `{id, ended_on}` остаётся в
`archive_ids.json` на 365 дней. Импортёр одновременно переносит прошедшие записи и
чистит истёкший архив:

```bash
npm run import -- --india /path/india.html --russia /path/russia.html \
  --additional-russia /path/moscow.html --today 2026-09-05
```

Импортёр напрямую понимает табличную и карточную разметку стартовых HTML. Дополнительный
российский файл объединяется с федеральным по городу, пересекающимся датам, официальной
ссылке и сходству названия. Для HTML импортёр один раз генерирует детерминированные ID;
после импорта эти ID нельзя пересоздавать при изменении события. CSV может использовать
английские поля из `events.json` или русские заголовки:
`категория`, `дата начала`, `дата окончания`, `название`, `город`, `площадка`,
`описание`, `официальная ссылка`, `статус`, `добавлено`, `обновлено`. Поле `id`
обязательно: импортёр намеренно не генерирует нестабильные ID и останавливается на
дублях.

## Поведение Telegram

Главное меню: «Бизнес в Индии», «Индия в России», «Ближайшие», «Новые». «Ближайшие»
сначала предлагает Россию или Индию и показывает только ещё не начавшиеся события.
«Новые» берёт ID из фактических публикаций после bootstrap, поэтому стартовый импорт
не попадает в этот раздел. В обоих географических разделах доступны месяцы и города;
для России дополнительно есть категории «Бизнес», «Культура», «Практики». Москва
показывается первой. После выбора бот оставляет на экране одну карточку: стрелки
редактируют это же сообщение и листают события без засорения чата. Счётчик показывает
позицию в подборке; карточку можно открыть на официальном сайте, переслать обычной
функцией Telegram или отправить через кнопку «Поделиться».

Команда `/start` включает персональную рассылку, `/stop` выключает её. Ежедневный cron
в 09:00 по Москве читает GitHub и отправляет всем активным подписчикам только новые ID
и существенные версии. Для каждого chat ID хранится факт доставки, поэтому повторный
запуск не дублирует карточки. Первый `bootstrap` запоминает стартовый массив без
массовой рассылки. Повторный bootstrap заблокирован.

## Настройка и деплой

1. Создать отдельный GitHub-репозиторий либо поместить каталог `data/` в выбранный
   репозиторий. В `wrangler.jsonc` указать owner, repo и пути.
2. Установить зависимости, создать D1: `npx wrangler d1 create russia-india-events-bot`,
   записать полученный `database_id` в `wrangler.jsonc`.
3. Добавить секреты через `wrangler secret put`: `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_WEBHOOK_SECRET`, `SYNC_SECRET`; для приватного
   GitHub также `GITHUB_TOKEN` с доступом только на чтение Contents.
4. Выполнить `npm run db:remote`, `npm run check`, `npm run test`, `npm run deploy`.
5. Установить Telegram webhook на
   `https://<worker>/telegram/webhook`, передав `secret_token`, равный
   `TELEGRAM_WEBHOOK_SECRET`.
6. Один раз вызвать `POST /sync` с `Authorization: Bearer <SYNC_SECRET>` и телом
   `{"mode":"bootstrap"}`. Далее cron работает самостоятельно; ручной мониторинг —
   тот же endpoint с `{"mode":"monitor"}`.

`GET /healthz` возвращает только состояние сервиса и явно подтверждает отсутствие AI
и парсинга в runtime.
