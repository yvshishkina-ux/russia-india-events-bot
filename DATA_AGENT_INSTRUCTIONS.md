# Инструкция агенту, обновляющему календарь

Работай только с `data/events.json` и `data/archive_ids.json`. Telegram-бот ничего не
исследует и не исправляет: в GitHub должна попадать уже проверенная, короткая и готовая
к публикации карточка.

1. Сначала прочитай оба файла целиком. Не удаляй будущие события только потому, что их
   не было в текущей поисковой выдаче.
2. Поддерживай окно от сегодняшней даты до `сегодня + 120 дней`. Событие подходит, если
   начинается внутри окна и подтверждено официальным источником.
3. Для нового события задай постоянный человекочитаемый `id` в нижнем регистре. Перед
   добавлением проверь его отсутствие и в active, и в архиве. ID не меняется при
   переносе, смене города, отмене или правке ссылки.
4. География означает место проведения: `IN` или `RU`. Категория — только `business`,
   `culture`, `practices`. Для России связь с Индией должна быть содержательной, а не
   случайным участием одной компании.
5. `official_url` ведёт на официальный сайт организатора/события. Не используй поисковую
   выдачу, агрегатор или публикацию без подтверждения даты.
6. При добавлении заполни `added_at` и `updated_at` сегодняшней датой. При обновлении
   сохрани исходный `added_at`; меняй `updated_at`. Перенос, отмена и переход в онлайн
   меняют существующую запись, а не создают новую.
7. После завершения удали полную карточку из `events.json` и добавь в
   `archive_ids.json` только `{ "id": "...", "ended_on": "YYYY-MM-DD" }`. Удаляй
   архивные следы старше `retention_days`.
8. Не добавляй вычисляемое поле `upcoming` и не записывай Telegram publication ID:
   актуальность вычисляется по датам, публикации хранит D1.
9. Перед commit проверь валидный JSON, уникальность ID, `end_date >= start_date`, HTTPS
   в официальной ссылке и отсутствие одного ID одновременно в active и archive.

Существенные поля для уведомления канала: даты, город, статус, официальная ссылка.
Редактура описания или площадки не должна создавать новый ID.
